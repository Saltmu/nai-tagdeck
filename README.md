# nai-tagdeck

NovelAI Diffusion V5 向けのプロンプトを、タグの ON/OFF で組み立てる非公式ツールです。作ったプロンプトをコピーして NovelAI で使うことも、アプリ内で画像を生成することもできます。

**[ブラウザで nai-tagdeck を開く](https://shishio.x0.to/nai-tagdeck/)**

[使い方](#使い方) · [保存と移行](#保存と移行) · [ローカル開発](#ローカル開発) · [公開手順](#公開手順) · [辞書ファイルの形式](#辞書ファイルの形式)

## 使い方

### 1. 初回案内で始め方を選ぶ

- **タグの例と辞書を読み込む** — ベースとキャラクター1人分の例から試せます。
- **タグ辞書だけ読み込む** — 日本語で検索できる辞書を使い、プロンプトは自分で組み立てます。
- **何も読み込まずに始める** — 自分のタグや辞書を使って始めます。

後から選び直すには、「設定」の「初回案内をもう一度表示」を使います。編集中のベースやキャラクターがある場合は、タグの例で置き換える前に確認が出ます。

### 2. 「編集」でタグを組み立てる

| 編集対象 | 入れる内容 |
| --- | --- |
| ベース | 人数（`2girls` など）、画風、構図、背景など、画像全体に共通するタグ |
| キャラクター | キャラクターごとの種類（`girl` など）、外見、衣装、ポーズ。タブ右端の「＋」で追加 |
| ネガティブ | 画像全体の Undesired Content。初期値は公式 UI の UC プリセット「heavy」相当。下部で全キャラクター共通のネガティブも編集可能 |

- **タグを追加する** — ベース・キャラクターでは、上部の入力欄でカテゴリを横断して辞書の候補を探せます。カテゴリを指定して追加する場合は、そのカテゴリの入力欄を使います。NovelAI からコピーしたプロンプトを貼り付けて「追加」を押すと、カンマ区切りや重みの記法を読み取ってタグに分けます。
- **タグ一覧を絞る** — 一覧見出しの虫眼鏡で追加済みのタグを検索できます。「表示」メニューから ON のタグだけに絞ったり、カテゴリをまとめて開閉したりできます。
- **タグを調整する** — チェックを外したタグは、編集画面に残したまま出力から外せます。タグ名は鉛筆アイコンから編集でき、変更は編集中のプロンプトに反映されます。重みは −3〜3 の範囲で直接入力するか、−／＋ で 0.05 ずつ調整します。「並べ替え」でカテゴリ内の順序を変更できます。
- **生成に使うキャラクターを選ぶ** — キャラクターは最大15人まで保存できます。タブのチェックで、同時に最大6人を出力・生成に含められます。

### 3. プロンプトをコピーするか、画像を生成する

**NovelAI に貼り付ける場合**は、生成画面下部の「プロンプト」を開き、ベース・ネガティブ・キャラクターごとにコピーします。編集画面でもカテゴリ単位やキャラクター単位でコピーできます。

出力は ON のタグをカンマ区切りで並べた文字列です。「強調の記法」で数値式（`1.2::tag::`）と括弧式（`{tag}`、`[tag]`）を切り替えられます。0 以下の重みは常に数値式になり、`-1::hat::` のように負の重みを使うと要素を取り除く指定になります。

**アプリ内で生成する場合**は、以下の手順で設定します。

1. NovelAI のアカウント設定で「Get Persistent API Token」を使ってトークンを発行し、nai-tagdeck の「設定」→「NovelAI のトークン」に保存します。保存先は「このタブだけ」か「このブラウザに保存」を選べます。
2. 画面下部の「生成」でモード、サイズ、ステップ、シードなどを確認し、「生成」を押します。「ケモノ」モードでは、送信時にベースプロンプトの先頭へ `fur dataset` が付きます。このツールで指定できる範囲は 1024×1024 相当以下、28 ステップ以下、1 回につき1枚です。
3. 画像一覧から画像を拡大したり、PNG をダウンロードしたりできます。拡大表示から、その画像のシードを次の生成に設定できます。

### 辞書とプリセット

- **辞書**には再利用したいタグを登録します。日本語名やよみ、既定の重みも設定でき、JSON / CSV で入出力できます。「初期カテゴリを復元」は、不足する初期タグを補いつつ、登録済みタグのカテゴリや日本語名、重み、並び順を維持します。
- **プリセット**には、ベース・ネガティブ・キャラクターのタグ一式をまとめて保存します。プリセット欄の「…」を開き、「新しいプリセットとして保存」で名前を付けます。読み込み後は同じメニューの「変更を上書き」で更新できます。ネガティブ対応前のプリセットを読み込む場合、現在のネガティブを引き継ぎます。

## 保存と移行

| データ | 保存先・移行方法 |
| --- | --- |
| 辞書・プリセット・作業中のタグ・設定 | ブラウザに自動保存。「設定」の「バックアップを書き出す」で、別の端末やサイトに移せる JSON を作成 |
| NovelAI のトークン | 設定時に選んだタブまたはブラウザに保存。移行先では再設定 |
| 生成画像 | タブのメモリに一時保存。再読み込みやタブを閉じる前に、必要な画像を PNG でダウンロード |

バックアップを読み込むと、辞書とプリセットは追加・上書きされ、作業中のタグと設定はファイルの内容に置き換わります。「設定」の「Dangerゾーン」から、このブラウザの保存データとトークン、生成画像をまとめて削除できます。

画像生成時は、プロンプト・生成設定・トークンをブラウザから `image.novelai.net` へ直接送信します。一度読み込んだアプリはホーム画面に追加でき、オフラインでもプロンプトを編集できます。画像生成には通信が必要です。

## ローカル開発

以下は Node.js 24 系（24.15.0 以上）と npm を使う起動手順です。リポジトリのルートで実行します。

```bash
npm ci
npm run dev
```

起動後、ターミナルに表示された URL を開きます。

| コマンド | 用途 |
| --- | --- |
| `npm test` | Vitest でテストを実行 |
| `npm run typecheck` | TypeScript の型チェック |
| `npm run build` | 型チェック後、公開用の静的ファイルを `dist/` に出力 |
| `npm run preview` | ビルド後の `dist/` をローカルで確認 |

開発時に参照するコードと既存の回帰テストは [AGENTS.md](AGENTS.md)、生成リクエストの調査記録は [NovelAI 画像生成 API メモ](docs/novelai-api.md) を参照してください。

## 公開手順

`npm run build` で作った `dist/` の中身を、静的サイトとして配信します。アセットは相対パスのため、サブディレクトリにも配置できます。公開環境ではサーバー側で HTTPS へリダイレクトを設定します。HTTPS で配信すると、Service Worker によるオフライン編集を利用できます。

<details>
<summary>GitHub Actions から SFTP でアップロード</summary>

公開サーバーで SFTP の公開鍵認証またはパスワード認証が利用できる場合に使えます。国外 IP からのパスワード認証を制限しているホスティング（さくらのレンタルサーバの国外IPアドレスフィルタ等）では、公開鍵認証（`DEPLOY_SSH_KEY`）を使用してください。GitHub の **Settings → Environments** で `production` を作成し、Variables と Secrets を登録します。

| 種別 | 名前 | 設定値 |
| --- | --- | --- |
| Variable | `DEPLOY_HOST` | WinSCP の SFTP 接続先ホスト名 |
| Variable | `DEPLOY_PORT` | SFTP ポート（省略時は 22） |
| Secret | `DEPLOY_USER` | SFTP ユーザー名 |
| Variable | `DEPLOY_DIR` | `/home/user/www/nai-tagdeck` のような、SFTP で見える既存の公開ディレクトリの絶対パス |
| Secret | `DEPLOY_SSH_KEY` | SFTP 公開鍵認証用の秘密鍵（パスフレーズなし）。`DEPLOY_PASSWORD` より優先して使用 |
| Secret | `DEPLOY_PASSWORD` | SFTP ユーザーのパスワード（`DEPLOY_SSH_KEY` 未設定時に使用） |
| Variable | `DEPLOY_HOST_FINGERPRINT` | WinSCP の「タブ → サーバー／プロトコル情報」またはホスティング事業者で確認済みの SFTP サーバーの SHA-256 指紋（`SHA256:…`） |

実行時に公開サーバーのホスト鍵を取得し、登録済みの指紋に一致する鍵で SFTP 接続を検証します。以前の `DEPLOY_KNOWN_HOSTS` 変数は削除できます。

`DEPLOY_HOST_FINGERPRINT` が未設定の状態で dry-run を実行すると、ランナーから観測した指紋の候補だけをログに表示します。この実行では SFTP ログインや配付のプレビューは行いません。WinSCP またはホスティング事業者で照合した指紋を登録してから、再度 dry-run を実行します。

**Actions → Deploy nai-tagdeck → Run workflow** で `main` を選び、まず **Preview files without uploading** をオンにしたまま実行します。接続と転送予定を確認したら、チェックを外して再実行します。毎回テストとビルドを実行し、ハッシュ付きアセットを先に送ります。サイズが同じアセットは再送しません。その後にページを公開し、配信された `index.html` と `sw.js` がビルドと一致してから、`dist/` に無いファイルを削除します。サーバー側の `.htaccess` と `robots.txt` は残します。公開直前に古いページを開いていたタブは、古いスクリプトが削除されると再読み込みするまで開けないことがあります。

</details>

<details>
<summary>Windows から WinSCP でアップロード</summary>

1. [設定例](deploy/config.example.json) を `deploy/config.local.json` にコピーし、WinSCP の保存済みセッション名と公開先ディレクトリを設定します。
2. `npm run deploy -- --dry` で、アップロードと削除の対象を確認します。
3. `npm run deploy` でテスト・ビルドを実行し、公開先を `dist/` に同期します。公開先だけにあるファイルは削除対象です。サーバーで管理する `.htaccess` などは `keep` に指定します。

<details>
<summary>配信設定と検索エンジン向けの設定</summary>

- ビルド時に `index.html` へ CSP が入り、通信先を配信元と `image.novelai.net` に制限します。画像は `blob:` のみを許可します。`frame-ancestors 'none'` は meta では効かないため、[Apache の設定例](deploy/htaccess.example) の HTTP ヘッダーに含めています。キャッシュ制御も同じ設定例を参照してください。
- 変更後のページを取得できるよう、Service Worker はページ本体の取得をサーバーから試みます。通信に失敗したときは、その `sw.js` に埋め込んだビルド時のページを使います。相対パスのアセットは、サブディレクトリに置いたときのページ URL から解決します。通信で得た HTML ではそのキャッシュを上書きしません。新しい版があるときは画面の案内から再読み込みします。アイコンを再生成する場合は `node scripts/make-icons.mjs` を実行します。
- 公開 URL を変更する場合は、[`index.html`](index.html) の canonical・SNS 共有用 URL と [サイトマップ](public/sitemap.xml) をそろえます。現在の公開 URL は `www` なしの `shishio.x0.to` を使用します。
- 検索に掲載する場合は、認証なしで公開し、robots.txt や `X-Robots-Tag` の設定でクロール・インデックス登録を許可します。ビルドに含まれる `sitemap.xml` を Google Search Console に送信します。robots.txt は [設定例](deploy/robots.txt.example) を参考に、ドメイン直下の既存ルールに統合します。

</details>

## 辞書ファイルの形式

<details>
<summary>JSON・CSV の例とカテゴリ一覧</summary>

JSON は `entries` を持つオブジェクトか、タグの配列を読み込めます。

```json
{
  "app": "nai-tagdeck",
  "version": 1,
  "entries": [
    { "tag": "blonde hair", "category": "appearance", "alias": "金髪 きんぱつ" }
  ]
}
```

CSV は1行目に列名を指定します。どちらの形式も必須項目は `tag` と `category` です。任意項目は `id`、`alias`、`default_weight`、`sort_order`、`updated_at` です。

```csv
tag,category,alias
blonde hair,appearance,金髪 きんぱつ
```

`category` には以下のキーまたは表示名を指定できます。旧形式の `dress_state`（着衣状態）は、読み込み時に「衣装」に統合されます。

| キー | 表示名 |
| --- | --- |
| `quality` | 品質 |
| `style` | 画風 |
| `subject` | 被写体・人数・関係性 |
| `appearance` | 外見 |
| `outfit` | 衣装 |
| `pose` | ポーズ |
| `effect` | エフェクト |
| `composition` | 構図 |
| `background` | 背景・場所 |
| `weather` | 時間・天候 |
| `negative` | ネガティブ |

辞書の「追加・上書き」は、ID またはカテゴリとタグの組み合わせが一致する項目を更新します。「すべて置き換え」は、読み込んだ内容で辞書全体を置き換えます。初期タグを復元するときは、タグの大文字・小文字、全角・半角、アンダースコアなどの表記差を吸収して同名タグを照合します。

</details>
